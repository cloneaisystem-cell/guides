Connect Claude to your Instagram: free setup, 4 fixes and my prompts

Connect Claude Code to your own Instagram with the free MCP server mcpware/instagram-mcp: MIT license, 23 tools, the official Instagram Graph API and no password. Claude reads your comments and drafts replies. You approve before anything is posted.

Free guide · 0 creditsofficial APIno password23 tools
On your phone? Send yourself this link and open it on your computer. Claude Code doesn't run on a phone.
Never use a repo that asks for your Instagram password. Meta's terms forbid automated logins with a password, and in my assessment that can get your account banned. This setup uses Meta's official API with a token instead. Your password stays with Instagram.

What you need

  • Claude Code (it needs a paid Claude plan).
  • An Instagram professional account (Business or Creator) linked to a Facebook Page.
  • Python and git on your computer. Check with python --version and git --version.

The 7 steps

  1. Link your account to a Facebook Page

    In Instagram, switch to a professional account and connect it to a Facebook Page. Meta needs this link for the API.

  2. Register as a developer

    Go to developers.facebook.com and register with the same Facebook login.

  3. Create an app

    Click Create app. The name can't contain "Instagram". Meta rejects it, and some other brand words too. Pick something like "My Social Agent".

  4. Choose the use case

    Pick Manage messaging & content on Instagram. Open it and add the content and messaging permissions, including comments and insights. If you see "Something went wrong", press OK and try again. It took me two tries.

  5. Get your token

    Open the Graph API Explorer, pick your app and a User Token, and add these 8 permissions: 
    instagram_basic
instagram_content_publish
instagram_manage_comments
instagram_manage_insights
instagram_manage_messages
pages_show_list
pages_read_engagement
business_management

    Click Generate Access Token and approve. Then open Meta's Access Token Debugger, paste the token and click Extend Access Token. The new token lasts about 60 days. Keep the token private. Never post it or paste it in a chat.

  6. Install the server

    In a terminal: 
    git clone https://github.com/mcpware/instagram-mcp
cd instagram-mcp
python -m venv .venv
.venv/Scripts/activate        # Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt

    Then create a file named .env in that folder. Use placeholders like these and paste your own values:

    INSTAGRAM_ACCESS_TOKEN=paste_your_token_here
INSTAGRAM_BUSINESS_ACCOUNT_ID=paste_your_instagram_account_id_here
FACEBOOK_APP_ID=paste_your_app_id_here
FACEBOOK_APP_SECRET=paste_your_app_secret_here

    Never share this file or commit it to git. The server needs all four lines to start.

  7. Add it to Claude Code and restart

    In your project folder, add the server to .mcp.json: 
    {
  "mcpServers": {
    "instagram": {
      "command": "/path/to/instagram-mcp/.venv/bin/python",
      "args": ["-m", "src.instagram_mcp_server"],
      "cwd": "/path/to/instagram-mcp"
    }
  }
}

    On Windows the python path is .venv\Scripts\python.exe. If your setup ignores cwd, point command at a tiny launcher script that goes into the folder and runs the same python -m src.instagram_mcp_server line. Then restart Claude Code and check that the instagram server shows up.

The 4 fixes I needed

The repo needed four small changes before it worked for me. Tell Claude Code to make them, or edit the files yourself.

1. The server crashes on start

Problem: the newest mcp library (version 2) breaks it with 'Server' object has no attribute 'list_tools'. Fix: pin it in requirements.txt, then reinstall.

mcp<2

2. Your token prints in the logs

Problem: the httpx library logs every request URL, and the URL contains your token. Fix: right after the logging setup in src/instagram_mcp_server.py, turn those loggers down.

logging.getLogger("httpx").setLevel(logging.WARNING)
logging.getLogger("httpcore").setLevel(logging.WARNING)

3. Messages fail with "An unknown error has occurred."

Problem: the DM endpoints need the Page token, not your user token. Fix: fetch the Page token once and use it for the messaging calls.

GET /me/accounts?fields=id,access_token,instagram_business_account

Take the access_token of the Page whose instagram_business_account is yours, and send it with every DM request.

4. Reading a conversation errors out

Problem: the messages field is built with a double closing brace, messages{...}}, which is a syntax error. The message model also expects text but gets objects. Fix, in src/instagram_client.py and src/models/instagram_models.py:

params = {"fields": "messages{" + fields + "}", "limit": min(limit, 100)}

from_id: Any = Field(..., alias="from")
to: Any
attachments: Optional[Any] = None

My prompts

Step 1. Claude drafts, nothing is posted:

Read the comments on my most recent reel that has comments. Draft a short, friendly reply to each one in my voice. Don't post anything until I say OK.

Step 2. You read the drafts, fix what you want, then say:

OK, post them

Optional. Check the inbox (it only reads):

Check my Instagram inbox. Tell me which conversations have a new message and what each one says. Don't reply to anything.

Treat DMs as private. Claude can see them once you connect the server. Keep write actions (posting, replying, sending DMs, deleting) on "ask me first".

Limits to know

  • 100 API-published posts per 24 hours.
  • DMs: you can reply only within about 24 hours after the person wrote to you first.
  • 5 hashtags max per post.
  • Media must be at a public HTTPS URL to be published.
  • Your token lasts about 60 days. Then extend it again in the Access Token Debugger.
